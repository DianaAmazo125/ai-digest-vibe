# AI-Дайджест — витрина нейросетей

Небольшой сайт-каталог нейросетей и ИИ-сервисов, доступных в России без VPN. Все карточки лежат в
одном JSON-файле, поэтому сайт обновляется правкой данных, а не кода: добавили объект в `data.json` —
на странице появилась новая карточка вместе с кнопкой своей категории.

Сейчас в каталоге **29 карточек** в 10 категориях — от китайских и российских моделей до мировой
четвёрки (Claude, ChatGPT, Cursor, Gemini).

Проект задуман как контентная площадка: карточки ведут на сервисы (в том числе по партнёрским ссылкам),
на странице есть места под рекламные блоки Яндекс.РСЯ, а партнёрские карточки помечены маркировкой
рекламы с токеном `erid`.

## Что умеет

- выводит карточки нейросетей из `data.json` — с категорией, описанием и ссылкой;
- живой поиск по названию карточки прямо во время набора;
- фильтрация по категориям: кнопки строятся автоматически из данных, поэтому список кнопок всегда
  совпадает с реальными категориями в файле;
- счётчик найденных карточек (`Найдено: N из общего числа`) — обновляется при поиске и фильтрации;
- поддержка партнёрских ссылок: если у карточки заполнено поле `affiliate_url`, посетитель идёт по нему,
  а не по основной ссылке, и такая ссылка помечается как рекламная (`rel="sponsored nofollow"`);
- маркировка рекламы: если у карточки заполнен `erid`, под описанием появляется плашка
  `Реклама. <рекламодатель> · erid: …` (рекламодатель берётся из поля `advertiser`);
- кнопки официальных площадок проекта — Telegram-канал и ВКонтакте — в шапке и в подвале сайта;
- подвал с пояснением про партнёрские ссылки и маркировку рекламы;
- два места под рекламные блоки РСЯ: широкий баннер над сеткой карточек и блок внутри сетки после
  второй карточки.

## Технологии

| Компонент | Что используется |
|---|---|
| Бэкенд | Python + Flask 3 |
| WSGI-сервер | gunicorn (в продакшене), встроенный сервер Flask — локально |
| Шаблоны | Jinja2 (входит в Flask) |
| Фронтенд | чистый HTML, CSS и JavaScript — без сборки и фреймворков |
| Конфигурация | `python-dotenv` |
| Деплой | Amvera Cloud (окружение Python + pip, конфиг `amvera.yml`) |
| Дизайн | CSS Grid + стеклянные карточки (glassmorphism), анимация фона на CSS |

Внешних CDN-зависимостей у вёрстки нет, кроме подключения шрифта Inter с Google Fonts.
Иконки соцкнопок сделаны моно-бейджами на CSS, без картинок и сторонних библиотек.

## Установка и запуск

1. **Создайте виртуальное окружение и активируйте его**

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

   В Linux/macOS: `python3 -m venv .venv && source .venv/bin/activate`

2. **Установите зависимости**

   ```powershell
   pip install -r requirements.txt
   ```

3. **Создайте файл `.env` из примера**

   ```powershell
   Copy-Item .env.example .env
   ```

4. **Сгенерируйте секретный ключ и впишите его в `.env`**

   ```powershell
   python -c "import secrets; print(secrets.token_hex(32))"
   ```

   Полученную строку подставьте в переменную `SECRET_KEY`. Если её не задать, приложение запустится
   с отладочным значением `dev-secret-key` — для локальной проверки это нормально, для публикации нет.

5. **Запустите сайт**

   ```powershell
   python app.py
   ```

   Откройте http://127.0.0.1:5000 — сервер запускается в режиме отладки (`debug=True`), поэтому
   изменения в шаблонах и коде подхватываются автоматически. Остановить — `Ctrl+C`.

   В продакшене приложение поднимается не встроенным сервером Flask, а gunicorn (см. раздел про Amvera).
   На Windows gunicorn не работает — локально используйте `python app.py`.

## Как добавить или изменить карточку

Все карточки лежат в `data.json` — это массив объектов. Одна карточка выглядит так:

```json
{
    "id": 1,
    "title": "DeepSeek V3.2 (DeepSeek Chat)",
    "desc": "Короткое описание: что делает сервис и почему он полезен.",
    "tag": "china",
    "tag_name": "Китайские модели",
    "cpa_url": "https://chat.deepseek.com",
    "affiliate_url": "",
    "erid": ""
}
```

| Поле | Обязательное | Что означает |
|---|---|---|
| `id` | да | Номер карточки, должен быть уникальным |
| `title` | да | Заголовок карточки, по нему же работает поиск |
| `desc` | да | Описание в 1–2 предложения |
| `tag` | да | Машинный код категории (например, `china`) |
| `tag_name` | да | Название категории, которое видит посетитель и по которому работает фильтр |
| `cpa_url` | да | Основная ссылка карточки |
| `affiliate_url` | нет | Партнёрская ссылка. Если заполнена — используется вместо `cpa_url` и помечается как реклама |
| `erid` | нет | Токен маркировки рекламы (ОРД). Если заполнен — в карточке появится плашка «Реклама … · erid: …» |
| `advertiser` | нет | Рекламодатель для плашки, например `ИП Вергус Е.Е., ИНН 614101552625`. Без него плашка выводится в коротком виде «Реклама · erid: …» |

Новая категория не требует правок в шаблоне: достаточно указать новое значение `tag_name`, и кнопка
фильтра появится сама. Поле `tag` остаётся для служебных нужд и как запасной вариант, если `tag_name`
не заполнен.

## Маркировка рекламы (erid)

Для партнёрских карточек заполняются три поля:

```json
{
    "cpa_url": "https://sovetywebmastera.pro?erid=CQH36pWzJq…",
    "affiliate_url": "https://sovetywebmastera.pro/school-new?gcao=28266&gcpc=1f1e7&erid=CQH36pWzJq…",
    "erid": "CQH36pWzJq…",
    "advertiser": "ИП Вергус Е.Е., ИНН 614101552625"
}
```

Правила, по которым это устроено:

- токен `erid` дублируется в целевых ссылках: к адресу без параметров он добавляется как `?erid=…`,
  к ссылке с существующими параметрами (`gcao`, `gcpc` и т. п.) — как `&erid=…`;
- `affiliate_url` остаётся партнёрской ссылкой с трекингом, поэтому кнопка на карточке ведёт именно
  по ней, а `cpa_url` служит резервным адресом;
- текст плашки формируется в шаблоне: `Реклама.` + рекламодатель + `· erid: <токен>`;
- без заполненного `erid` никакой плашки на карточке не появляется — маркировка не выдумывается.

## Деплой на Amvera

В корне проекта лежит `amvera.yml` — конфигурация сборки и запуска:

```yaml
meta:
  environment: python
  toolchain:
    name: pip
    version: "3.12"
build:
  requirementsPath: requirements.txt
run:
  command: gunicorn -w 2 -b 0.0.0.0:80 app:app
  containerPort: 80
```

Что здесь важно:

- `version: "3.12"` указана в кавычках: без них YAML превратил бы значение в число `3.1`, и Amvera
  собрала бы приложение на неправильном образе Python;
- в `requirements.txt` должен быть `gunicorn` — Amvera ставит зависимости из этого файла;
- `containerPort: 80` совпадает с портом из команды `-b 0.0.0.0:80`. Если приложение слушает другой
  порт, поменяйте оба значения, иначе сайт отдаст 502 при статусе «Приложение запущено»;
- `app:app` — это модуль `app` и объект Flask `app` внутри него.

Порядок публикации:

1. закоммитьте изменения и отправьте их в репозиторий, который подключён к приложению Amvera
   (`git push origin master` при связке с GitHub или `git push amvera master`, если Amvera выступает
   основным remote);
2. в личном кабинете Amvera в разделе «Переменные и секреты» добавьте `SECRET_KEY` (иначе сайт
   поднимется с отладочным ключом) и, при желании, `PYTHONUNBUFFERED=1`, чтобы логи из `print`
   сразу появлялись в журнале приложения;
3. после пуша Amvera сама запускает сборку — статус и причины ошибок видно в логах сборки и приложения.

Про данные: каталог карточек (`data.json`) лежит в репозитории, а не в постоянном хранилище, поэтому
контент обновляется коммитом. Если приложение когда-нибудь начнёт сохранять изменяемые файлы, писать
их нужно в `/data` (папка `data` в репозитории и каталог `/data` — разные вещи: содержимое репозитория
при пересборке откатывается к версии коммита).

## Структура проекта

```
digest_site/
├── app.py                  # Flask-приложение: загрузка data.json, сбор категорий, рендер страницы
├── data.json               # база карточек — весь контент сайта (29 карточек)
├── requirements.txt        # зависимости Python (Flask, python-dotenv, gunicorn)
├── amvera.yml              # конфигурация сборки и запуска для Amvera Cloud
├── .env.example            # шаблон переменных окружения (можно публиковать)
├── .env                    # ваш реальный SECRET_KEY (в Git не попадает)
├── .gitignore              # исключает .env и служебные файлы
├── static/
│   └── style.css           # оформление: космический фон, стеклянные карточки, плашка erid, соцкнопки
└── templates/
    └── index.html          # вёрстка страницы, шапка и подвал с кнопками площадок, поиск и фильтры
```

## Где подключать рекламу РСЯ

В `templates/index.html` подготовлены два контейнера с идентификаторами:

- `#yandex_rtb_top` — широкий баннер над сеткой карточек;
- `#yandex_rtb_grid` — блок внутри сетки, выводится после второй карточки.

Вставьте в них код из кабинета Яндекс.РСЯ вместо текстовых заглушек.

## Безопасность

`SECRET_KEY` читается из переменной окружения, а не хранится в коде. Файл `.env` внесён в `.gitignore`
и в репозиторий не попадает — публикуйте только `.env.example` с пустым значением. На Amvera ключ
задаётся в разделе «Переменные и секреты».
